Write `tasks/prd-<slug>.md`. The user cannot answer questions mid-run, so state assumptions explicitly instead of asking.
Sections: goal, users, user stories (each with numbered acceptance criteria that can be verified by a command or a browser check), non-goals, technical constraints, open questions, success metrics.
Every story must be small enough for one focused iteration. Mark stories that change UI with `[UI]`.
